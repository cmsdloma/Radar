Supported Formats

Five feed formats, one unified map

Radar understands five distinct feed formats, each with its own parsing pipeline. Wherever a feed item carries geographic coordinates — whether embedded in XML tags, GeoJSON geometry, or KML placemarks — those coordinates are extracted and rendered as interactive POI on the live map.

GeoRSS 🌍

GeoRSS / Geo-Atom

Standard RSS or Atom feeds that embed geographic coordinates directly inside each item — via georss:point, geo:lat/lon, or GML geometry elements. The most widely used format for open-data geospatial alert feeds from meteorological agencies, fire services, earthquake networks and tsunami centres.

  • Parses georss:point, georss:polygon, geo:lat/geo:long
  • Also handles GML gml:pos and gml:coordinates
  • Each geo-tagged item → interactive POI on the map
  • 36 curated sources included
Map POI Earthquakes · Fires · Floods
CAP 🚨

CAP – Common Alerting Protocol

The international XML standard for emergency alerts, endorsed by WMO and OASIS. CAP messages carry structured severity, urgency and certainty fields alongside geographic area definitions — including both point coordinates and polygon boundaries that are drawn directly onto the map.

  • Full CAP 1.2 parsing — severity, urgency, certainty, category
  • Area polygon boundaries drawn as map overlays
  • Centroid coordinate → map POI marker
  • 120+ curated feeds covering 50+ countries
Map POI + Polygons Official Government Alerts
GeoJSON 🗺️

GeoJSON REST APIs

REST API endpoints that return GeoJSON FeatureCollections (or wrapped feature arrays). Each feature is parsed by the GeoJSON feed fetcher — the properties become a message entry and, where coordinates are present, a map POI. Covers real-time earthquake catalogs, wildfire perimeters, flood boundaries and more.

  • Parses GeoJSON Point, LineString, Polygon geometry
  • Feature properties → structured message with title, time, detail
  • Coordinates → live map POI for every feature
  • 60+ curated API sources included
Map POI Earthquake Catalogs · Fire Perimeters
RSS 📰

Standard RSS / Atom

Plain news-style RSS and Atom feeds without embedded coordinates. These deliver text-based intelligence — government advisories, cybersecurity bulletins, disease outbreak notifications, humanitarian crisis updates, and aviation or maritime safety reports. Items appear as messages in the feed stream, not as map pins.

  • Full RSS 2.0 and Atom 1.0 parsing
  • Titles, descriptions, published dates and source links preserved
  • 44 curated sources covering cyber, health, government, humanitarian
  • No map POI — intelligence feed only
Intelligence Feed Cyber · Health · Government
KML 📌

KML – Keyhole Markup Language

Keyhole Markup Language files from geographic data portals, national mapping agencies, and open-data platforms. KML placemarks, points and path data are parsed and each placemark coordinate becomes a map POI. Add any KML-serving URL via the custom feeds manager.

  • Parses KML Placemark and Point elements
  • Coordinates → interactive map POI
  • Add custom KML sources via the feeds manager
  • Compatible with Google Maps KMZ/KML export format
Map POI Custom Data · GIS Portals
Geo Extraction & Map Integration

From feed item to map pin — automatically

Every geo-capable feed format is parsed end-to-end in the background. You don't configure coordinates — Radar extracts them, normalises them and places them on your live map as interactive POI.

📡 Feed fetched & parsed

Each enabled feed is polled at its configured interval — as fast as every minute for critical alert feeds. The raw XML, JSON, or KML is parsed by the format-specific fetcher (GeoRSS, CAP, GeoJSON, KML).

📍 Coordinates extracted

The fetcher reads the latitude and longitude from whichever geo field the format uses — georss:point, GeoJSON geometry, CAP <area>, or KML Placemark. CAP feeds also extract polygon boundary coordinates for overlay rendering.

🗺️ POI placed on your map

Each geo-tagged item becomes a live POI marker on the interactive map, positioned at the extracted coordinates. CAP alerts additionally draw their polygon boundaries as shaded area overlays on the map.

ℹ️ Tap a pin for detail

Tap any feed POI to see the title, source feed name, description and any severity or metadata the original feed provided. A link to the original source is preserved where available.

🔄 Stale pins auto-removed

Feed markers are managed in real time — items no longer present in the latest fetch are automatically removed from the map. You always see current data, not stale markers from hours ago.

📐 Zoom-adaptive icons

Feed POI icons scale with the map zoom level in stepped bands, so the map stays readable at any zoom — whether you're looking at a global overview or zoomed in on a neighbourhood.

Feeds Manager

Add your own. Manage everything.

The curated library is just the starting point. Radar's feeds manager lets you add any custom feed URL, enable or disable individual feeds, and control how often each one refreshes.

➕ Add custom feeds

Paste any GeoRSS, CAP, GeoJSON, RSS or KML URL — Radar auto-detects the format and adds it to your feed list. Perfect for local emergency services, specialist data portals, or organisation-specific feeds.

✅ Enable / disable per feed

Each curated and custom feed can be individually toggled on or off. Enable only the regions and hazard types relevant to you, or disable feeds when you don't need them to save bandwidth and battery.

🔄 Configure refresh intervals

Each feed has a sensible default refresh interval — typically 5–15 minutes for critical alert feeds and 30–60 minutes for slower-moving data. High-frequency feeds like Pikud HaOref (Israel) refresh as often as every minute.

🗺️ Geo feeds → live map POI

Any feed carrying coordinates — whether you added it or it came from the curated library — automatically places interactive POI on your map. Tap any pin to see the event title, source, and details.
